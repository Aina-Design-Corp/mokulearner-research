How to contribute

The whole contribution happens on the GitHub website — no software installation required. Register once, fork the repository, add your data and metadata, and open a pull request. Automated validation and a community maintainer take it from there.

The workflow at a glance

  1. Register as a contributor (GitHub issue — one time only)
  2. Fork the repository — this creates your own copy to edit
  3. Add your data to contributions/{your-slug}/{dataset-slug}/
  4. Include a metadata.json (use the template)
  5. Open a pull request — GitHub Actions validates automatically

New to GitHub, or want each step spelled out with what you'll see on screen? Use the interactive walkthrough on the dashboard — it walks the same workflow one step at a time. If your lab already uses Git for code, the same workflow applies to data; the full written guide is in CONTRIBUTING.md.

What you provide — and what you don't

Required fields for every contribution.
FieldRequiredDescription
Data fileYesCSV or GeoJSON with your research data
TitleYesHuman-readable name for the dataset
Contribution typeYesobservation, indicator, or spatial_overlay
TopicsYesWhat domain your research addresses (e.g. water, demographics)
LicenseYesOpen data license (CC-BY-4.0 recommended)
Quality levelYespreliminary, verified, or peer_reviewed
SchemaYesColumn names and types in your data file
Sample contextFor observationsWhat was physically collected (soil, water, sediment, etc.)
Baseline contextFor indicatorsWhich Data Commons variables your data supplements
CoverageWhen neededText description of geographic scope (only if data lacks coordinates)

You do NOT need to provide: moku district IDs (auto-derived from coordinates, or inferred from your coverage description), SDG codes (auto-derived from your topic selections), or baseline comparisons (the platform links your data to county-level Data Commons indicators automatically).

Topic taxonomy

Contributions are tagged with topics from a controlled vocabulary. Each topic maps to ISO 37101 community sustainability issues and aligns with Data Commons baseline indicators. SDG codes are assigned automatically from your topic selections.

Quality levels

LevelMeaningReview
preliminaryRaw field data, not yet QA'dSpot-check
verifiedQA'd by contributor, methods documentedStandard review
peer_reviewedPublished or reviewed by external partyFast-track

Preliminary data is welcome — the quality level is a declaration, not a gatekeep. Labs can upgrade quality by submitting a follow-up PR with updated metadata.

Licenses

All contributions must use an open data license:

  • CC-BY-4.0 (recommended)
  • CC-BY-SA-4.0
  • CC-BY-NC-4.0
  • CC0
  • ODbL
